Documentation aspects that are not fully aligned with the system requirements:

1. Medium: NFR-02 minimum precision threshold can be weakened by request configuration

- Why:
  RF model activation is now correctly gated on validation weighted precision.
  However, POST /rf/train accepts activation_threshold from the request payload.
  An authenticated admin can therefore configure a threshold below the required
  NFR-02 minimum of 80%.

- Evidence:
  - Validation and test metrics are computed before activation.
  - _get_activation_status() archives models below the configured threshold.
  - /rf/train allows activation_threshold to be supplied by the caller.

- Requirement impact:
  NFR-02 requires at least 80% precision on labeled datasets. The activation
  mechanism should enforce 0.80 as a hard minimum, while optionally allowing
  stricter thresholds.

Resolved since previous review:

1. FR-08 (OAuth/RBAC/org isolation)
   RESOLVED.
   All protected routes require a validated Supabase bearer token. /rf/train
   requires the admin role and _enforce_org_scope() prevents a request org_id
   from differing from the authenticated user's organization.

2. FR-05 / UC-03 (MITRE-oriented classification)
   RESOLVED.
   RF attack-class predictions are passed through an explicit CICIDS-to-MITRE
   mapping layer that returns ATT&CK techniques, confidence, and
   confidence-adjusted severity.

Aligned with the requirements:

1. FR-10 (REST API)
2. FR-01 / FR-02 (ingestion and storage)
3. NFR-06 (containerization / CI-CD)
